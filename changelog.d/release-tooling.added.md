- Stdlib-only release toolchain under `tools/`: `tools/changelog.py` manages conflict-free `changelog.d/` fragments (each PR adds its own file, so changelogs never merge-conflict) and `tools/release.py X.Y.Z` cuts a release in one command — assembling the pending fragments into a dated `CHANGELOG.md` section, bumping the version in all five authored files (`ward/__init__.py`, `pyproject.toml`, PKGBUILD, the RPM spec with a correctly-dated `%changelog` stanza, and the native `debian/changelog`), then committing and tagging `vX.Y.Z` for the release workflow. See `RELEASING.md`.
